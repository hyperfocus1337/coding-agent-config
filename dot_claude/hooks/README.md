# hooks

Hooks run on agent events, for example after each `Write` or `Edit`, before a `Bash` call, or when the agent stops. Each hook is one folder here, with its TypeScript code and its own README. `toggle-hook` is the exception: it runs only when you type `/toggle-hook`, not on an agent event, and turns the advisory hooks off or on. It is here and not in [`mods/`](../mods/README.md) because its `HOOKS` list names those hooks, and it has a pi and omp adapter.

Each hook has one TypeScript core with an adapter for each agent: a Claude Code mod, a pi and omp extension, and a Codex command hook. `lint-code`, `type-check-tsc`, and `type-check-pyrefly` run as command hooks in Claude Code, not as mods. Three hooks in the table are git hooks in [`dot_config/git/hooks/`](../../dot_config/git/hooks/), not agent hooks: git runs them on each commit, for each agent. A mod needs Claude Code 2.1.296 or later, the oldest version tested. [`docs/hooks/`](../../docs/hooks/README.md) gives the design, the rules to write a hook, the API facts of each agent, and the decisions.

`just hooks-check` type-checks the moved hooks and their tests, validates each mod with `claude plugin validate`, and runs the `test/check.ts` of each hook that has one. It reads the Claude Code types that the engine writes into `~/.claude/hooks/<hook>/.claude-plugin/types/`, so run it after `just chezmoi` and one interactive Claude Code session. A `claude -p` run does not write them. The Node types come from the `@types/node` of [`scripts/extensions/hooks/package.json`](../../scripts/extensions/hooks/package.json). The check runs `pnpm install --frozen-lockfile` when `node_modules` is missing or older than `pnpm-lock.yaml`.

## Shared conventions

**A failed tool call still changed the disk.** `PostToolUse` fires only after a tool call succeeds; a shell command that exits non-zero raises `PostToolUseFailure`. A command that writes a file and then fails a check has still written the file, so a hook that acts on Bash must run on both. A mod on `tool.call` and a pi `tool_result` handler see every result, and so does Codex `PostToolUse`. A command hook in Claude Code needs entries on both events. A hook that reports through `hookSpecificOutput` must echo `.hook_event_name` back rather than hardcode it, because `hookEventName` is the discriminant of a per-event schema.

**A path a command names is not always a path it wrote.** Some formatters extract paths from Bash commands and use modification times to select recent files. Code linting does not parse shell commands: it selects changed files from git at stop time. `lint-prose` runs on Bash, but it takes the changed files from the snapshot log of `track-session-changes`, not from the command text or an mtime.

**Formatting on edits, code checks at stop time.** Formatters act on tool results. Code lint and type checks wait until the agent is about to stop, then give one correction opportunity. `Stop` carries no file path, so these hooks ask git what changed and use `stop_hook_active` as a loop guard. Pi uses `agent_before_settle` to collect findings for one correction run, with guards reset at `agent_settled`.

**Fail open or fail closed, on purpose.** The advisory formatting hooks swallow failures and exit 0, so a hiccup never blocks a tool call. The lint and type-check hooks exit 2 to surface the error or the block back to Claude. The git guards exit 1, which stops the commit and puts the block message in the output of `git commit`.

**Self-disable when a tool is missing.** A hook checks for its linter, formatter, or scanner and exits 0 when the tool is absent, so a fresh machine is never blocked on an uninstalled dependency.

**Dependencies.** Each command hook needs `node` 23.6 or later, which runs a `.ts` file. pi and omp run `pi.ts` and `omp.ts` in their own runtime. The tools of each hook are in the table above, and each hook README tells how to install them.

**A missing `node` gives a warning.** A command entry that runs a `.ts` file starts with `command -v node >/dev/null || exit 0`, so a machine with no `node` does not get an error on each call. Then the hook does not run, so a `SessionStart` entry in Claude Code and in Codex checks once for each session that `node` can run a `.ts` file (`process.features.typescript`). If it cannot, the entry prints a `systemMessage`, which both agents show as a warning, with the list of hooks that are off. pi and omp load `pi.ts` and `omp.ts` in their own runtime and need no `node` on `PATH`.

**A missing `node` blocks a commit.** The git guards `block-secret-commits` and `block-commit-attribution` fail closed. With no `node` on the `PATH` of git, their hook command blocks each commit with a message that names the problem.

**One switch for the supported hooks.** `AGENT_HOOKS_DISABLE` lists the hooks that are off, separated by spaces or commas. The formatters, `lint-code`, `lint-prose`, the type checkers, and `block-destructive-commands` read it on each run, and do nothing when it names them. [`/toggle-hook`](toggle-hook/README.md) changes it in the running agent. In Codex, set it at launch.

The other guards do not read the variable, and `format-staged-files` removes it before it runs the formatters. Turning off `block-destructive-commands`, including through `all`, skips all dcg checks. This includes the `--no-verify` block, so an agent can then skip the git guards.

**One switch for each repository.** The same hooks also do nothing when the git config of the repository of a file sets `agent-hook.<hook>.enabled` to `false`. `format-code` also reads `agent-hook.format-code.terraform`, `agent-hook.format-code.shfmt`, and `agent-hook.format-code.ruff`. `/toggle-hook --repo <hook>` writes the key, and the key applies across sessions and in `format-staged-files`. The dcg pack `local.agent_hook` blocks an agent command that writes the key.

**Per-repo escape hatches.** `block-secret-commits` reads `.agent-allow-secrets` and `.betterleaksignore`; `enforce-cli-tools` reads `.agent-allow-cli-tools`. Both also accept an environment variable for a one-off override. See the hook README for the exact names. Keep an `.agent-allow-*` file out of git with `.git/info/exclude`, not `.gitignore`.

**A test that commits turns off `format-staged-files`.** In an agent session, an agent variable such as `CLAUDECODE=1` is set, so `git commit` in a fixture repository under `$HOME` starts the global pre-commit hook. The hook formats the fixture before the commit, so the commit does not hold the text that the test wrote. Put these lines in each test that commits, before the first commit. They turn off only this hook and keep the other global settings:

```sh
export GIT_CONFIG_COUNT=1
export GIT_CONFIG_KEY_0=hook.format-staged-files.enabled GIT_CONFIG_VALUE_0=false
```

A fixture under `/tmp` or `$TMPDIR` does not need them, because the formatters skip those directories.

**Deliberate shortcuts** carry a `shortcut:` comment naming the ceiling and the upgrade path, matching the marker `rules/code.md` defines.
