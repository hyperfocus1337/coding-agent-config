# hooks

Hooks run on agent events, for example after each `Write` or `Edit`, before a `Bash` call, or when the agent stops. Each hook is one folder here, with its TypeScript code and its own README.

Each hook has one TypeScript core with an adapter for each agent: a Claude Code mod, a pi and omp extension, and a Codex command hook. `block-secret-commits`, `type-check-tsc`, and `type-check-pyrefly` run as command hooks in Claude Code, not as mods. A mod needs Claude Code 2.1.296 or later, the oldest version tested. [`docs/hooks/`](../../docs/hooks/README.md) gives the design, the rules to write a hook, the API facts of each agent, and the decisions.

`just hooks-check` type-checks the moved hooks and their tests, validates each mod with `claude plugin validate`, and runs the `test/check.ts` of each hook that has one. It reads the Claude Code types that the engine writes into `~/.claude/hooks/<hook>/.claude-plugin/types/`, so run it after `just chezmoi` and one interactive Claude Code session. A `claude -p` run does not write them.

## Shared conventions

**A failed tool call still changed the disk.** `PostToolUse` fires only after a tool call succeeds; a shell command that exits non-zero raises `PostToolUseFailure`. A command that writes a file and then fails a check has still written the file, so a hook that acts on Bash must run on both. A mod on `tool.call` and a pi `tool_result` handler see every result, and so does Codex `PostToolUse`. A command hook in Claude Code needs entries on both events. A hook that reports through `hookSpecificOutput` must echo `.hook_event_name` back rather than hardcode it, because `hookEventName` is the discriminant of a per-event schema.

**A path a command names is not always a path it wrote.** A Bash payload carries no file path, so a hook that acts on Bash reads the paths out of the command text. That text also holds the files the command only read. A formatter can reformat one of those without harm, but a linter that blocks on it stops a read on an error that was already there, so `lint-code` lints a named path only when its mtime says the command just wrote it. That mtime also changes when another process writes the file, so `lint-prose`, which blocks on old paragraphs too, does not run on Bash.

**One file, or the whole project.** A hook that acts on the edited file runs on `PostToolUse` and reads `.tool_input.file_path`. A hook that reads the whole project runs on `Stop`, once per turn, because `PostToolUse` would rerun it after every edit and reprint the same unrelated errors each time. `Stop` carries no file path, so such a hook asks git what changed and reads `.stop_hook_active` to avoid blocking every stop.

**Fail open or fail closed, on purpose.** The advisory formatting hooks swallow failures and exit 0, so a hiccup never blocks a tool call. The lint, type-check, and secret-commit hooks exit 2 to surface the error or the block back to Claude.

**Self-disable when a tool is missing.** A hook checks for its linter, formatter, or scanner and exits 0 when the tool is absent, so a fresh machine is never blocked on an uninstalled dependency.

**Dependencies.** Each command hook needs `node` 23.6 or later, which runs a `.ts` file. pi and omp run `pi.ts` and `omp.ts` in their own runtime. The tools of each hook are in the table above, and each hook README tells how to install them.

**A missing `node` gives a warning.** A command entry that runs a `.ts` file starts with `command -v node >/dev/null || exit 0`, so a machine with no `node` does not get an error on each call. Then the hook does not run, so a `SessionStart` entry in Claude Code and in Codex checks once for each session that `node` can run a `.ts` file (`process.features.typescript`). If it cannot, the entry prints a `systemMessage`, which both agents show as a warning, with the list of hooks that are off. `block-secret-commits` does not exit 0: its `guard.sh` blocks each `git commit` instead. pi and omp load `pi.ts` and `omp.ts` in their own runtime and need no `node` on `PATH`.

**One switch for the advisory hooks.** `CLAUDE_HOOKS_DISABLE` lists the hooks that are off, separated by spaces or commas. The formatters, `lint-code`, `lint-prose`, and the type checkers read it on each run, and do nothing when it names them. [`/toggle-hook`](toggle-hook/README.md) changes it in the running agent. In Codex, set it at launch. The guards do not read it, and `format-staged-files` removes it before it runs the formatters.

**Per-repo escape hatches.** `block-secret-commits` reads `.agent-allow-secrets` and `.betterleaksignore`; `enforce-cli-tools` reads `.agent-allow-cli-tools`. Both also accept an environment variable for a one-off override. See the hook README for the exact names. Keep an `.agent-allow-*` file out of git with `.git/info/exclude`, not `.gitignore`.

**A test that commits turns off `format-staged-files`.** In an agent session, an agent variable such as `CLAUDECODE=1` is set, so `git commit` in a fixture repository under `$HOME` starts the global pre-commit hook. The hook formats the fixture before the commit, so the commit does not hold the text that the test wrote. Put these lines in each test that commits, before the first commit. They turn off only this hook and keep the other global settings:

```sh
export GIT_CONFIG_COUNT=1
export GIT_CONFIG_KEY_0=hook.claude-format-staged.enabled GIT_CONFIG_VALUE_0=false
```

A fixture under `/tmp` or `$TMPDIR` does not need them, because the formatters skip those directories.

**Deliberate shortcuts** carry a `shortcut:` comment naming the ceiling and the upgrade path, matching the marker `rules/code.md` defines.
